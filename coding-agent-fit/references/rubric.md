# Coding Agent 接入评测标准 (Rubric v6)

评测云服务、API 平台或开发者工具对 Coding Agent 的支持程度：开发者把接入任务交给 Claude Code、Cursor、Codex、Trae 等 Coding Agent 之后，Agent 能否找到入口、读懂资料、写出代码、真正跑通，并且长期可靠。

评测前先确认三件事：

1. 目标网站提供什么服务。
2. 用户的接入需求是什么（默认按站点典型任务推一个，并和用户确认）。
3. 从发现入口到跑通第一个调用，Agent 中间可能卡在哪。

## v6 计分总纲：基线 + Agent 双轨

```
基线得分 (0-60)  = 60 × max(0, 1 − Σ实际扣分 / Σ适用项满扣)     ← 扣分制
Agent 得分 (0-40) = Σ (维度 R × 维度权重) × 40                  ← R 加分制
Agent 实得分      = min(Agent 得分, 基线得分 × 2/3)             ← 耦合规则
总分             = 基线得分 + Agent 实得分
```

- **基线轨**：行业标配项清单，每项三档判定——完整（扣 0）/ 部分（扣 half）/ 缺失（扣 full）。标配项做到位不加分，缺失才扣分。
- **Agent 轨**：只计 Agent 增量项，沿用 R 证据比 + 权重 + 1-5 档 + 置信度全套机制。
- **耦合规则**：基线 60 → Agent 上限 40（不受限）；基线 30 → Agent 顶多 20。基础文档不达标时，辅助工具的加分同步受限。

## 站点类型

| 类型 | 说明 |
|------|------|
| 云服务 / API 平台 | 在线服务、REST/GraphQL API、SDK、控制台、密钥或 OAuth 接入 |
| 开发者工具 | 主要提供 CLI、SDK、框架、构建工具或本地工具链 |
| Agent 工具 | 主要提供 MCP、Skill、Agent 配置、工具服务或流程模板 |

混合型站点按主要接入任务对应的类型取一套；任务 50/50 时取两套加权平均，报告里写明用了哪套。

**纯文档站点（知识库、教程、参考文档，没有可接入的 API 或工具）不在评测范围**——没有"接入"就没有评测对象，阶段 4.5 实跑也无从执行。阶段 1 识别到时告知用户，确认是否改评文档背后的实际服务。

## 基线轨（60 分，扣分制）

共识标配清单。每项判三档：**完整 = 扣 0 / 部分 = 扣 half / 缺失 = 扣 full**。每项判定必须有 URL 证据并标 T 级；探测被拦或未验证到的项单独列出，不计扣分但压低置信度（见置信度评级）。资源存在但内容读不到（如 status page 是 SPA 壳、返回 200 但正文无法确认）按"部分"计，报告注明"存在但未能确认内容"。

站点类型列是**适用性标记**：✓ 适用（缺了扣分）/ — 不适用（不计入 Σ适用项满扣，不是缺失）/ △ 视站点实际形态判断。

| # | 基线项 | 满扣 | 云服务 | 开发者工具 | Agent 工具 |
|---|--------|------|--------|-----------|-----------|
| B1 | 文档公开可访问，无登录墙 | 10 | ✓ | ✓ | ✓ |
| B2 | API reference / 命令参考 / 工具 schema 完整 | 12 | ✓ | ✓(命令参考) | ✓(工具与配置参考) |
| B3 | 鉴权说明：key 获取路径 + 使用方式 | 8 | ✓ | △(需账户时) | ✓ |
| B4 | quickstart / 入门指引，按文档能跑通 | 7 | ✓ | ✓ | ✓ |
| B5 | 错误码 / 常见错误 / 退出码说明 | 5 | ✓ | ✓ | ✓ |
| B6 | 限流 / 重试 / 超时等生产细节 | 3 | ✓ | — | △(remote 服务时) |
| B7 | 官方 SDK 或安装分发方式 + 可复制示例 | 5 | ✓ | ✓ | ✓ |
| B8 | 无销售墙 / 人工审批即可开始使用 | 6 | ✓ | ✓ | ✓ |
| B9 | 示例与当前版本一致，无过期示例 | 4 | ✓ | ✓ | ✓ |
| B10 | changelog / release notes 存在 | 3 | ✓ | ✓ | ✓ |
| B11 | status page 或可用性信息 | 2 | ✓ | — | △(remote 服务时) |
| B12 | 求助渠道：support / issues / 社区 | 2 | ✓ | ✓ | ✓ |
| B13 | TLS 证书有效 | 3 | ✓ | ✓ | ✓ |

```
基线得分 = 60 × max(0, 1 − Σ实际扣分 / Σ适用项满扣)
```

云服务全项适用时 Σ适用项满扣 = 70。举例：quickstart 部分（−3.5）+ changelog 部分（−1.5）→ 基线 = 60 × (1 − 5/70) = 55.7。

**三档判定标准示例**（其余项类推——"部分"指存在但有实质缺口）：

| 项 | 完整 | 部分 | 缺失 |
|----|------|------|------|
| B2 API ref | 端点/参数/响应全 | 只有索引或部分端点 | 无 reference |
| B4 quickstart | 复制即跑 | 一两处需手改/路径难找 | 无或全跑不通 |
| B3 鉴权 | 获取路径+用法+scope | 只有用法没有获取路径 | 无说明 |
| B10 changelog | 有且条目可定位 | 入口存在但条目难追 | 无 |

v5 的硬规则（"缺 API ref → 档 ≤3"）已被基线扣分吸收，不再单列。

## Agent 轨（40 分池，R 加分制）

只计 Agent 增量项。每个维度算三个值：

- **证据比 R**
  - 正向维度（A1/A2/A3/A5）：`R = 实际证据点 / 证据上限`
  - 反向维度（A4）：`R = max(0, 1 - friction / 10)`
- **定性档 1-5**：由 R 映射，统一档带（A4 用 friction_ratio 锚点）：

| R | 维度档 |
|---|--------|
| 0.85-1.00 | 5 |
| 0.65-0.84 | 4 |
| 0.45-0.64 | 3 |
| 0.25-0.44 | 2 |
| 0.00-0.24 | 1 |

- **置信度**：高 / 中 / 低，机械算出，不进分数（见置信度评级）。

```
维度贡献 = R × 维度权重 × 40
Agent 得分 = Σ 维度贡献
Agent 实得分 = min(Agent 得分, 基线得分 × 2/3)
```

### Agent 轨权重

| 维度 | 云服务 / API 平台 | 开发者工具 | Agent 工具 |
|------|----|----|----|
| A1. Agent 入口与发现 | 15% | 10% | 10% |
| A2. 文档直接可读 | 30% | 25% | 20% |
| A3. Agent 工具 | 30% | 40% | 45% |
| A4. Agent 专属摩擦 | 15% | 15% | 15% |
| A5. 维护信号可跟踪 | 10% | 10% | 10% |

### A1. Agent 入口与发现（上限 12）

Agent 不靠人指路，能不能自己发现站点提供的全部 Agent 资源。

| 证据 | 分值 |
|------|------|
| `llms.txt` 位于根路径或文档挂载路径，指向关键文档 | 3 |
| `llms-full.txt` 或分层 / 分产品子索引 | 3 |
| Link header / HTML link / `X-Llms-Txt` 主动声明这些资源的位置 | 2 |
| well-known 发现文件（mcp.json / skills index / api-catalog）：一种 2 分，两种以上 3 分 | 3 |
| robots.txt 明确允许主流 AI bot | 1 |

**注意**：根路径 `/llms.txt` 404 不能直接判缺失。必须检查文档挂载路径（`/docs/llms.txt`、`/developer/llms.txt` 等）和子域（`docs.host` / `developer.host` / `api.host`）。

### A2. 文档直接可读（上限 16）

Agent 不解析 HTML，能不能直接拿到不带页面噪声的文档内容。

| 证据 | 分值 |
|------|------|
| 页面 `.md` 版本或 `Accept: text/markdown` 协商全站可用 | 4 |
| API spec 文件直接可下载（OpenAPI / GraphQL schema / API catalog，不需要经别的产品中转） | 4 |
| llms 生态深度：分产品 / 分语言子文件、llms-full 全量文本 | 3 |
| AI Agent / LLM 专属章节（best practices、Agent 接入指引） | 3 |
| 文档 URL 可预测：从索引可推断，按常见约定猜测能命中 | 2 |

### A3. Agent 工具（上限 16）

服务方为 Agent 直接调用做了多少投入。

| 证据 | 分值 |
|------|------|
| CLI Agent 化：非交互模式、JSON / 结构化输出、稳定退出码 | 3 |
| CLI 自检：doctor / verify / dry-run 类命令 | 2 |
| MCP server：transport、鉴权、工具 schema、验证方式完整 | 4 |
| IDE / runtime 配置示例（Claude Code / Cursor / Codex / Trae 中两个及以上） | 3 |
| 官方 Skill / AGENTS.md / rules / prompt pack | 3 |
| 工具版本化发布 + 官方仓库 | 1 |

**计分规则**：

- 生态级工具（平台通用而非本产品专属，如全云平台的 mcp-proxy）按 0.5 计，报告注明"非产品专属"。
- 只有 URL、无配置 / 鉴权 / schema 的 MCP 按 0.5 计，同时触发 A4"有宣传无配置"扣分。
- CLI 本身存在属于基线 B7；这里只计 Agent 化增量。

### A4. Agent 专属摩擦（friction_max = 10，扣分制）

只收主要影响 Agent、对人类开发者影响很小的摩擦；人机都受影响的摩擦（登录墙、销售墙、示例过期）归基线轨。各项独立相加，10 封顶。

| 扣分项 | 分值 |
|--------|-----|
| 核心文档是 SPA 壳 / 依赖 JS 渲染，且没有 `.md` 等可直接读取的替代版本 | 2.5 |
| 反爬 / robots / 内容策略阻断 AI bot 抓取 | 2.5 |
| 软 404：不存在路径返回 200 错误页，污染机器探测 | 2 |
| llms.txt / `.md` 等资源与 HTML 页面内容不一致或过期 | 1.5 |
| Agent 资源（MCP / Skill / llms.txt）有宣传无可用配置 | 1.5 |

```
R = max(0, 1 − friction / 10)
```

| friction_ratio | 维度档 | 判断 |
|----------------|-------|------|
| 0.00-0.10 | 5 | 基本无 Agent 专属阻碍 |
| 0.11-0.25 | 4 | 有小摩擦，不影响主路径 |
| 0.26-0.45 | 3 | Agent 会遇到卡点 |
| 0.46-0.70 | 2 | 机器探测和抓取风险高 |
| 0.71+     | 1 | Agent 难以稳定获取资料 |

### A5. 维护信号可跟踪（上限 6）

changelog、弃用、版本发布这些维护信息，Agent 能不能程序化跟踪。changelog / status 的"存在"归基线 B10/B11；这里只计可跟踪的增量。

| 证据 | 分值 |
|------|------|
| changelog 提供 `.md` / RSS / JSON 版本，且 URL 可预测 | 2 |
| 弃用 / breaking change 能被程序发现（spec 标注、response header、结构化标记） | 2 |
| 版本发布记录能被程序查询（GitHub releases / registry） | 1 |
| Agent 可用的反馈通道（CLI issue 命令、API、issue 模板） | 1 |

## 置信度评级

置信度独立每维度算（A1-A5），不影响分数，但进入报告并影响 "Agent 接入把握" 的定性结论和改进建议排序。基线项判定同样标 T 级；有未验证基线项时在报告基线段列出，并把涉及维度的置信度视作有缺口。

**证据来源等级**

- **T1（强）**：直接读到原始内容 — llms.txt / OpenAPI / .md / `Accept: text/markdown`，或本地实跑验证
- **T2（中）**：HTML 页面已读取，引用具体段落
- **T3（弱）**：仅 page_signals 关键词命中、搜索标题、第三方仓库

**定义**

```
strong_ratio    = T1 命中证据项 / (总证据项 - N/A)
covered_ratio   = (T1 + T2 命中) / (总证据项 - N/A)
dry_run_verified = 本维度是否被阶段 4.5 实跑覆盖
```

**判定**

```
高    若 strong_ratio ≥ 0.5  且  (dry_run_verified 或 covered_ratio ≥ 0.8)
低    若 covered_ratio < 0.4  或  N/A 比例 > 0.4
中    其他
```

置信度评级在报告各维度详情段必须给出 `strong_ratio` / `covered_ratio` / `dry_run_verified` 三个具体值，不能只写"高/中/低"。总置信度 = worst-of（A1-A5）。

## 等级

| 等级 | 分数区间 | 读法 |
|------|----------|------|
| S | 90-100 | 基线项全部完整，Agent 支持投入深，Agent 基本可独立完成接入 |
| A | 80-89 | 基线项完整，Agent 支持有实质投入 |
| B | 70-79 | Agent 支持刚起步，提升空间明显 |
| C | 60-69 | 传统开发者可正常接入，但几乎没有面向 Agent 的投入 |
| D | 45-59 | 基线清单有缺失项，接入本身就有阻碍 |
| F | 0-44 | 缺少基本接入条件 |

等级读法：D / F 说明基线清单有缺失项，问题出在基础文档，与 Agent 无关；C 说明基线完整但缺少 Agent 投入；B 及以上的分差来自 Agent 轨得分。

最终报告除总分外，还要给出：

- **Agent 接入把握**：高 / 中 / 低（必须引用阶段 4.5 实跑结果，不能只凭静态分）
- **评测置信度**：高 / 中 / 低（= 总置信度）
- **人工介入点**：无需 / 需要拿 key / 需要补 API 判断 / 需要人工排障 / 需要联系销售或支持

## "最可能卡住的一步" 挑选规则

报告必须写出 Agent 最可能卡住的一步。按优先级挑：

1. 阶段 4.5 实跑实际卡住的位置（最硬证据）
2. 基线缺失项或 A4 扣分中，影响最大且无明显 workaround 的项
3. 多个候选时，选最早出现在接入流程里的（步骤 1 卡 > 步骤 5 卡）

## 实跑映射要求

阶段 4.5 实跑出现的卡点必须先映射：

- 人机通用卡点（key 难拿、示例跑不通、文档找不到）→ 基线清单对应项
- Agent 专属卡点（软 404、SPA、llms.txt / `.md` 等资源失效）→ A4 摩擦项
- 两边都映射不上 = 报告里提议新扣分项作为评测产出

## N/A 规则

基线轨的类型适用列已覆盖大部分异质性。Agent 轨 N/A 仅限一种：

- 评测对象实际能力范围之外（如纯前端工具不评 OAuth）

**不准 N/A**：

- 云服务 / API 平台缺 llms.txt、缺 CLI / MCP / Skill——都属于 Agent 轨要评的对象，让 R 自然偏低即可
- "小服务做不到"不构成 N/A 理由

N/A 时，该维度的证据上限按剩余有效证据项重算，报告说明原因。

## 计分示例

某云服务：基线 quickstart 部分（−3.5）、changelog 部分（−1.5），其余完整 → 基线 = 60 × (1 − 5/70) = **55.7**。
Agent 轨：A1 R=0.50、A2 R=0.53、A3 R=0.59、A4 friction=3.5 → R=0.65、A5 R=0.33
→ Agent 得分 = (0.50×0.15 + 0.53×0.30 + 0.59×0.30 + 0.65×0.15 + 0.33×0.10) × 40 = 0.541 × 40 = **21.6**
耦合检查：min(21.6, 55.7 × 2/3 = 37.1) = 21.6（不受限）
→ **总分 = 55.7 + 21.6 = 77.3（B 级）**：基础扎实，Agent 投入初步。
